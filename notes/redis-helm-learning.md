# Redis Helm Chart Learning Notes

This document records the Redis Helm chart work, the important commands, and the reason for each directory. Use it as a rereadable workflow when you need to maintain or republish the chart.

│       ├── Chart.yaml

## What each directory is for

### `charts/redis`

This is the source chart. Edit these files when changing Redis behavior:

- `Chart.yaml`: chart name and versions.
- `values.yaml`: configurable defaults.
- `templates/`: Kubernetes manifests generated by Helm.
- `README.md`: documentation for users of the chart.

Do not edit the packaged `.tgz` file directly. Make changes in this directory, validate them, then package a new chart version.

### `docs`

This is the directory currently published by GitHub Pages. It must contain the files required by a traditional Helm repository:

- `index.yaml`
- One or more packaged chart files ending in `.tgz`

The `.tgz` extension is correct. It means a compressed tar archive used as a Helm chart package.

The public Helm repository URL is:

```text
https://sudo0x.github.io/helm-charts
```

Helm automatically requests:

```text
https://sudo0x.github.io/helm-charts/index.yaml
```

Do not put personal notes in `docs` because GitHub Pages publishes this directory.

### `dist`

This is a local build/output directory. Helm writes packaged charts and the generated index here during development.

It is not automatically served by GitHub Pages. The publishable files are copied from `dist` into `docs`.

### `notes`

Use this directory for learning notes, command history, troubleshooting, design decisions, and maintenance procedures. Notes in this directory do not affect Helm packaging or the public Helm repository.

## The chart itself

The chart is named:

```text
sudo0x-redis
```

Its current versions are:

```yaml
version: 0.2.0
appVersion: "8.2"
```

`version` is the Helm chart package version. Increase it whenever chart files or behavior change.

`appVersion` identifies the Redis application version used by the chart. It normally follows the image tag.

The default image is:

```yaml
image:
  repository: redis
  tag: "8.2"
```

The chart uses:

- A single Redis StatefulSet.
- One Redis instance by default.
- A ClusterIP Service.
- A ConfigMap for `redis.conf`.
- A Secret for the Redis password.
- A PVC by default.
- Liveness and readiness probes.
- Non-root security settings.

This is not a high-availability design. It does not provide Sentinel, Redis Cluster, replication, automatic failover, or backups.

## Helm chart development workflow

Use Git Bash:

```bash
cd /d/dancypher
```

### 1. Edit the source chart

Make changes only under:

```text
charts/redis/
```

For example, configuration defaults are in:

```text
charts/redis/values.yaml
```

### 2. Validate the chart

Run linting:

```bash
cd /d/dancypher/charts/redis
helm lint .
```

Render the default chart without installing it:

```bash
helm template redis . -n infrastructure
```

Render important configuration variants:

```bash
helm template redis . -n infrastructure \
  --set auth.existingSecret=my-redis-secret \
  --set persistence.enabled=false
```

```bash
helm template redis . -n infrastructure \
  --set auth.enabled=false \
  --set persistence.enabled=false
```

Check the rendered output for:

- Secret creation or omission.
- Correct Secret name and key.
- ConfigMap containing `redis.conf`.
- Service and StatefulSet names.
- Correct probe commands.
- Correct password environment variable behavior.
- PVC versus `emptyDir`.
- `/data` and `/etc/redis/redis.conf` mounts.

### 3. Install or upgrade into Kubernetes

From `charts/redis`:

```bash
helm upgrade --install redis . \
  --namespace infrastructure \
  --create-namespace
```

Inspect the deployed resources:

```bash
kubectl get statefulset,service,secret,configmap,pvc -n infrastructure
kubectl get pods -n infrastructure -l app.kubernetes.io/instance=redis
```

Inspect a pod if it is not ready:

```bash
kubectl describe pod -n infrastructure \
  -l app.kubernetes.io/instance=redis
```

View logs:

```bash
kubectl logs -n infrastructure \
  -l app.kubernetes.io/instance=redis
```

## Authentication notes

Authentication is enabled by default:

```yaml
auth:
  enabled: true
  existingSecret: ""
  existingSecretKey: redis-password
  password: "change-me"
```

When `existingSecret` is empty, Helm creates a Secret for the chart. When it is set, Helm references that Secret and does not create another one.

To use a pre-created Secret:

```bash
kubectl create secret generic my-redis-secret \
  --from-literal=redis-password='replace-this-password' \
  --namespace infrastructure
```

Install with:

```bash
helm upgrade --install redis ./charts/redis \
  --namespace infrastructure \
  --set auth.existingSecret=my-redis-secret
```

Never commit real passwords into `values.yaml`, notes, shell history, or public Git repositories. The default `change-me` value is only a development placeholder.

## Persistence notes

Persistence is enabled by default:

```yaml
persistence:
  enabled: true
  size: 10Gi
```

The StatefulSet creates a PVC through `volumeClaimTemplates` and mounts it at `/data`.

For temporary testing only:

```bash
helm upgrade --install redis ./charts/redis \
  --namespace infrastructure \
  --set persistence.enabled=false
```

With persistence disabled, Helm uses `emptyDir`. Data is lost when the pod is removed or rescheduled.

## Publishing the chart as a Helm repository

The GitHub source repository stores the chart source. GitHub Pages serves packaged charts and `index.yaml`.

### 1. Increase the chart version

Before publishing a changed chart, edit `charts/redis/Chart.yaml`:

```yaml
version: 0.2.1
```

Every published chart version should be unique.

### 2. Package the chart

From the repository root:

```bash
cd /d/dancypher
mkdir -p dist
helm package charts/redis --destination dist
```

This creates a file such as:

```text
dist/sudo0x-redis-0.2.1.tgz
```

### 3. Generate the Helm repository index

```bash
helm repo index dist \
  --url https://sudo0x.github.io/helm-charts
```

The index contains chart metadata and the public download URL for each package.

### 4. Copy published files to `docs`

Clear old published files only when you intentionally want to remove old versions:

```bash
rm -f docs/*.tgz docs/index.yaml
```

Copy the current package and index:

```bash
cp dist/*.tgz docs/
cp dist/index.yaml docs/
```

Keeping older `.tgz` packages in `docs` allows users to install older chart versions. If old packages are removed, remove their entries from `index.yaml` by regenerating it from the packages that remain.

### 5. Commit and push

```bash
git add charts/redis docs
git commit -m "Publish sudo0x Redis Helm chart 0.2.1"
git push
```

The Git remote uses the SSH alias configured for the `sudo0x` account:

```text
git@github.com-sudo0x:sudo0x/helm-charts.git
```

### 6. Test the published repository

Wait for GitHub Pages to deploy, then run:

```bash
curl -I https://sudo0x.github.io/helm-charts/index.yaml
```

A successful response should be `HTTP/1.1 200 OK`.

Add the repository:

```bash
helm repo add sudo0x https://sudo0x.github.io/helm-charts
```

Update local repository metadata:

```bash
helm repo update
```

Search for the chart:

```bash
helm search repo sudo0x
```

Install from the published repository:

```bash
helm upgrade --install redis sudo0x/sudo0x-redis \
  --namespace infrastructure \
  --create-namespace
```

Install a specific chart version:

```bash
helm upgrade --install redis sudo0x/sudo0x-redis \
  --version 0.2.0 \
  --namespace infrastructure \
  --create-namespace
```

## GitHub SSH authentication

The SSH configuration uses a host alias:

```ssh
Host github.com-sudo0x
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_sudo0x
    IdentitiesOnly yes
```

The Git remote must use the alias, not plain `github.com`:

```text
git@github.com-sudo0x:sudo0x/helm-charts.git
```

Test authentication:

```bash
ssh -T git@github.com-sudo0x
```

This message means authentication succeeded:

```text
Hi sudo0x! You've successfully authenticated, but GitHub does not provide shell access.
```

The command may return exit code `1` because GitHub does not provide an interactive shell. That is normal.

If the remote uses `git@github.com:sudo0x/helm-charts.git`, the alias-specific key is not selected and GitHub may return:

```text
Permission denied (publickey).
```

Fix the remote with:

```bash
git remote set-url origin \
  git@github.com-sudo0x:sudo0x/helm-charts.git
```

## Common mistakes

### Helm repository returns 404 for `index.yaml`

Check that both files are inside the GitHub Pages directory:

```text
docs/index.yaml
docs/sudo0x-redis-0.2.0.tgz
```

Check the Pages URL:

```bash
curl -I https://sudo0x.github.io/helm-charts/index.yaml
```

If it returns `404`, verify GitHub Pages settings:

- Repository: `sudo0x/helm-charts`.
- Branch: `master`.
- Folder: `/docs`.

### Confusing GitHub source URLs with Helm repository URLs

This is a GitHub source/package URL:

```text
https://github.com/sudo0x/helm-charts/blob/master/dist/sudo0x-redis-0.2.0.tgz
```

This is the Helm repository URL:

```text
https://sudo0x.github.io/helm-charts
```

Helm needs the second URL because it reads `index.yaml` and discovers chart packages from it.

### Package is not visible after publishing

Check all of the following:

```bash
git status
git log --oneline -3
ls docs
cat docs/index.yaml
```

Then wait for GitHub Pages deployment and run:

```bash
helm repo update
helm search repo sudo0x
```

### Chart package was not updated

Helm identifies packages by chart version. Do not reuse `0.2.0` for changed content. Increase the chart version, package again, regenerate `index.yaml`, copy the files to `docs`, and push.
